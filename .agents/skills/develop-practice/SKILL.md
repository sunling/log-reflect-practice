# Develop Practice

把已经在生活中萌芽的东西整理成实践，不从一个孤立念头制造项目。

## 先检查证据

至少确认以下一项：

- 同一需要、问题或主题在多条记录中重复出现；
- 使用者已经采取过行动；
- 已收到来自自己、他人或环境的反馈。

如果都没有，建议继续留在 Daily 中观察，不创建 Practice。

## 步骤

1. 列出支持这项实践的记录日期或相对链接。
2. 和使用者确认实践名称、它服务的对象、当前边界与最小行动。
3. 在 `practices/<实践名>/` 创建：
   - `mission.md`：为什么存在、服务谁、做什么、不做什么；
   - `current.md`：当前假设、本轮行动、观察方式、下次回看时间。
4. 保留与来源记录的相对链接，让实践能够回到其生活证据。
5. 若目录已存在，优先更新 `current.md`，不要重复创建近义 Practice。

## 写作要求

- 使命写得具体，不使用宏大口号代替真实对象。
- 一轮只保留一个足够小的行动。
- 反馈可以是感受、行为变化、他人回应或可观察结果，不必强行量化。
- 明确写出“本轮不做什么”，保护实践边界。
