# Practices

Practice 是从记录中长出来、愿意持续尝试并接收反馈的行动，不是另一种资料分类。文章草稿可以成为表达练习的产物，但文章主题本身不是 Practice。每周回看本身仍存入 `reviews/`。

## 什么时候创建

至少出现以下一种证据时，再考虑建立 Practice：

- 同一需要或问题反复出现；
- 已经开始行动，想观察它带来的变化；
- 外部反馈推动你继续做下去。

## 最小结构

```text
practices/<实践名>/
├── mission.md   # 为什么做、服务谁、边界是什么
├── current.md   # 现在正在尝试什么、下一步是什么
└── drafts/      # 只有这项 Practice 会持续产生文章时才增加
```

需要更多文件时再增加，不要提前搭建复杂系统。可以参考 [`examples/practice/`](../examples/practice/)。

如果这项 Practice 是“每周写一篇”“持续公开表达”或“把输入写成自己的话”等输出练习，文章草稿放在：

```text
practices/<输出练习名>/
├── mission.md
├── current.md
└── drafts/
    └── YYYYMMDD-文章主题.md
```

- `<输出练习名>` 描述正在练习的行动，不要直接使用某一篇文章的主题；
- 同一篇文章后续继续更新同一个草稿文件，不自动创建 `v2`、`final` 等重复版本；
- 文章发布与否由使用者决定，进入 `practices/` 不等于已经公开。
